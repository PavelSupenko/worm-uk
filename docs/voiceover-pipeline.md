# Конвейер многоголосой озвучки (ElevenLabs Eleven v4)

Руководство по процессу, который сложился в проекте worm-uk. Его можно перенести в любой проект, где есть
текст с репликами разных персонажей: другую книгу, дубляж игры, аудиоспектакль. Конкретная реализация лежит
в `tools/` этого репозитория, навыки Claude Code — в `.claude/skills/`.

## Схема

```
текст с разметкой голосов
  → экспорт: куски по границам абзацев, реплики по голосам         tools/export_tts.py
  → агент расставляет теги эмоций и ударения, проверка слов          навык tts-tags, --check
  → генерация: один запрос Text to Dialogue на кусок               tools/voice_chapter.py
  → постобработка локально: распознавание, ускорение пояснений,
    громкость голосов, точные тайминги                              tools/audiopost.py (whisper.cpp)
  → прослушивание, переделка отдельных кусков
  → публикация: файл с хешем в имени в Cloudflare R2                 tools/voice_chapter.py --publish, tools/r2.py
```

Новая машина готовится одной командой `tools/setup.sh`: ffmpeg, whisper.cpp, модель с проверкой контрольной
суммы, проверка ключей. Ключи (`ELEVENLABS_API_KEY`, `R2_*`) живут в `~/.zshrc` и никогда не попадают в
репозиторий.

## 1. Разметка текста

- **Голос рассказчика задаётся один раз** на весь текст (`data-narrator`). Отдельно размечаются только чужие
  реплики (`data-voice`). Это вдвое сокращает разметку и почти исключает ошибки.
- **Ремарки остаются у рассказчика.** В `“…,” — сказала вона, — “…”` слова «сказала вона» стоят вне голоса
  персонажа, иначе их прочтёт персонаж. Валидатор предупреждает о таких местах.
- **Единица текста — абзац** (в игре — строка диалога). Озвучка режется строго по этим границам, поэтому деление
  текста на абзацы менять нельзя.
- **Реестр голосов** (`tts/voices.json`): ключ персонажа → описание, имя и ID голоса ElevenLabs, поправка громкости.

## 2. Кастинг голосов

1. Кандидатов ищем через API библиотеки (`/v1/shared-voices`) по типажу: пол, возраст, use case, ключевые
   слова (`teen`, `deadpan`, `gravelly`…).
2. Отсекаем голоса с `rate` > 1 (они дороже за символ) и с коротким `notice_period` (автор может убрать голос).
3. **Английские и европейские голоса на Eleven v4 отлично звучат по-украински.** Флаг проверенного языка
   (`verified_languages`) — плюс, но не обязательное условие.
4. Сначала слушаем английские превью, потом сэмплы на нужном языке по типажам.
5. **Окончательно выбираем только в сцене.** Один и тот же кусок с несколькими голосами персонажей: голос,
   хороший сам по себе, может не сочетаться с остальными.
6. Голос из библиотеки перед использованием через API нужно добавить в аккаунт
   (`/v1/voices/add/{public_owner_id}/{voice_id}`). Лимит — 30 голосов, лишние после выбора удаляем.
7. **Громкость не повод отказываться от голоса:** постобработка выравнивает голоса между собой. В worm-uk голоса
   Брайана и Лизы сначала отклонили как слишком громкие, а после появления поправок громкости вернули.

## 3. Экспорт

- **Куски до 1800 символов** из целых абзацев. Лимит API около 2000, остаток уходит на теги. Внутри куска
  соседние реплики одного голоса объединяются.
- В каждый запрос передаём `previous_text` и `future_text` (до 100 символов) из соседних кусков: так интонация
  не рвётся на швах.

## 4. Теги и ударения (агент)

- **Агент не меняет ни слова:** добавляет только теги `[…]` и знаки ударения. Проверка `--check` сравнивает
  текст без тегов и ударений с исходным.
- Теги — короткие английские указания перед словами, к которым относятся. Основные теги идут в диалогах;
  рассказчику — только на резких сменах тона и паузах сцены. В среднем один тег на 2–4 предложения диалога.
- **Прерванная реплика** («Дівчина з псами...» → пояснение → продолжение): `[breaks off mid-sentence]` перед
  обрывом и `[resuming, dry]` на продолжении. Без них модель заканчивает фразу затуханием, как законченное
  предложение. Смягчённый вариант без «rising» звучит лучше всего.
- **Теги скорости Eleven v4 игнорирует**, ползунков Speed/Style и SSML у v4 нет. Темп правим на постобработке.
- **Ударения:** v4 слушается комбинирующего знака ударения U+0301 после ударной гласной («Су́кою»). Заглавная
  гласная («СУкою») работает ненадёжно. Устойчивые случаи — в словарь `tts/stress.txt` (слово, ударная гласная
  заглавной); омографы (за́мок/замо́к, уку́си/укуси́) агент помечает в конкретной реплике. На сайте текст
  остаётся без знаков, они попадают только в текст для озвучки.
- **Имена в косвенных падежах** модель может прочитать с ударением на окончании (Луна́ вместо Лу́на). Такое имя
  вносим в словарь всеми формами.

## 5. Генерация

- Один кусок — один запрос Text to Dialogue со всеми голосами сцены: модель слышит контекст, и переходы между
  репликами получаются естественными. Поэтому реплики не озвучиваются по отдельности.
- Куски берём в MP3 128 kbps и один раз перекодируем в конце. Склейка MP3 без перекодирования даёт щелчки
  на швах.
- Кэш по отпечатку куска (текст, голоса, модель, формат): повторный запуск генерирует только изменённое.
  `--retake N` переделывает неудачный дубль.
- Изредка v4 читает слова рассказчика голосом соседнего персонажа (в worm-uk — рассказчицу голосом Лизы, оба
  голоса девичьи). Это случайная ошибка модели: её лечит новый дубль, обходные механизмы под неё не строим.

## 6. Постобработка (локально, whisper.cpp)

1. **Распознавание:** whisper.cpp (`ggml-large-v3-turbo-q5_0`, ~550 МБ, Metal на Apple Silicon) даёт время
   каждого слова; 2 минуты аудио — около 15 секунд.
2. **Сопоставление** распознанных слов с известным текстом (difflib). Получается 97–98% слов, остальные берут
   время у соседей. Так мы знаем начало и конец каждой реплики.
3. **Разрезы в середине пауз** между репликами, поэтому без щелчков.
4. **Ускорение пояснений** (рассказчик между двумя частями реплики одного персонажа): `atempo` 1,15×, высота
   голоса сохраняется. 1,2× показалось слишком быстрым.
5. **Громкость голосов:** у каждого голоса одна постоянная поправка к −20 LUFS (не больше ±8 дБ). Крик остаётся
   громче шёпота, выравниваются только голоса между собой. Поправка измеряется один раз на главе, где голос
   говорит не меньше 20 секунд, и хранится в реестре вместе с ID голоса. Если голос персонажа поменяют, он
   будет измерен заново.
6. **Швы между кусками:** тишина в начале и конце куска (ffmpeg `silencedetect`, порог −50 дБ) обрезается
   до 0,1 с, между кусками вставляется 0,25 с. Шов звучит как обычная пауза внутри куска (модель делает
   0,25–0,5 с), иначе ответ персонажа в начале следующего куска звучит как новый абзац. Тег паузы на краю куска
   сохраняет свою тишину.
7. **Итог:** вся глава ускоряется в 1,05 раза (`atempo`, поверх ускорения пояснений), одной линейной поправкой
   приводится к −18 LUFS, редкие пики выше −2 dBFS (крик) срезает лимитер, и глава кодируется в MP3 64 kbps
   моно (пик не выше −1 dBTP). Без лимитера один крик держал всю главу на 3,5 дБ тише цели. Тайминги абзацев точные,
   по первому слову абзаца с учётом обоих ускорений.

## 7. Публикация

- Cloudflare R2: 10 ГБ бесплатно, трафик не тарифицируется. Файл получает имя с хешем содержимого
  (`1.gestation/1.5-1a2b3c4d.mp3`), поэтому его можно кэшировать навсегда, а перезапись получает новый адрес.
- CORS бакета разрешает сайт: понадобится для офлайн-режима.
- Публикуем только то, что прослушано и одобрено.

## Цифры (Worm, арка 1)

- Глава — 9–15 тысяч символов (в среднем 12 тысяч), 8 кусков, около 15–20 минут аудио.
- Тариф Creator — 131 000 символов в месяц, то есть 8–10 глав с учётом переделок.
- Постобработка главы — 2–3 минуты на M1 Pro; повторный запуск с кэшем — секунды.

## Перенос в другой проект

- **Без изменений:** логика кусков и реплик, правила тегов и ударений, генерация, постобработка, публикация в R2,
  `tools/setup.sh`, навыки `tts-tags` и `voice-chapter`.
- **Адаптировать:**
  - формат исходного текста (в worm-uk его читает `tools/chapterlib.py`; нужен только список абзацев с репликами
    по голосам);
  - язык (`LANGUAGE`, флаг `-l` whisper.cpp);
  - словарь ударений;
  - место публикации.
- **Для дубляжа игр:**
  - единица — строка диалога со своим ID; куски — сцена или ветка диалога;
  - на выходе вместо склейки главы — отдельные файлы по границам реплик (разрезы постобработки уже их дают);
  - поправки громкости голосов нужны так же;
  - ускорение пояснений обычно не нужно;
  - время слов пригодится для липсинка.
